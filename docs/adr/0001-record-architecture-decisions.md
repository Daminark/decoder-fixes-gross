# 1. Record architecture decisions

Date: 2026-10-23

## Status

Accepted

## Context

Design decisions in this project need to be findable by a future maintainer without reconstructing them from the code or the history.

## Decision

Decisions that a maintainer would otherwise have to reverse-engineer are recorded here as Architecture Decision Records, after Michael Nygard's 2011 format: status, context, decision, consequences.
One numbered file per decision.
A substantive change is a new record that supersedes the old; typographical fixes and dated clarifications that do not change the decision may be made in place.

## Consequences

The records are public and should read well to a reviewer: a few crisp decisions, not a log of every choice.
Smaller choices live in the project's working notes and in commented tool configuration.
