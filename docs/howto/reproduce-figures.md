# Reproduce the figures

The results are produced in two stages.
Long commands write raw outputs to `data/`, which is not committed; a short aggregation command then reads them and writes the committed files in `results/`, from which the documentation renders every figure.
This page lists the commands of both stages in order.

## Stage one: lists and runs, to `data/`

Build the support lists and the trapping-set file from the Zenodo files, as `data/README.md` describes, in about 7 minutes:

```bash
uv run python scripts/build_lists.py
```

This writes `data/lists/u1.npz` to `u4.npz` and `data/lists/lets.npz`, and the record `results/lists.json` with their counts and hashes.

Then run each decoder over the lists, as [running a decoder over the support lists](run-tier1.md) describes.
Each run writes `data/runs/<run_id>/`; the Relay-BP baseline took 45 minutes on 8 workers.

## Stage two: aggregates, to `results/`

List every run to aggregate in `scripts/runs.toml`, with its run id, decoder and lists:

```toml
[[runs]]
id = "relay-bp-baseline"
decoder = "relay-bp-baseline"
lists = ["u1", "u2", "u3", "u4"]
```

Then regenerate the aggregates, in seconds:

```bash
uv run nox -s figures
```

This writes `results/floor_<run_id>.json` for each listed run and `results/ceiling.json`.
Each file names the hashes of its inputs (the run's files, the lists and the trapping-set file) and the commit of the code that wrote it.
The command stops if a run is incomplete, if its configuration names another decoder or other lists than its entry, if a list in `data/lists/` differs from the one the run decoded, or if `lets.npz`, `u3.npz` or `u4.npz` differs from the build recorded in `results/lists.json`; in the last case, rebuild the lists as in stage one.
[The floor estimate](../explanation/floor-estimate.md) explains what these files hold.

Run it from a clean checkout, so that the recorded commit carries no `-dirty` marker.

## Records with their own commands

Two files in `results/` are one-off records that `nox -s figures` does not regenerate.
`results/lists.json` is written by `scripts/build_lists.py` above.
`results/relay_version_check.json` compares the pinned relay-bp version with an earlier one on a committed sample, in about a minute:

```bash
uv run python scripts/check_relay_version.py
```

## Render the documentation

```bash
uv run nox -s docs
```

The build renders every figure from `results/`, so no figure image is committed.
The `results/` folder is regenerated by the commands above and never edited by hand.
